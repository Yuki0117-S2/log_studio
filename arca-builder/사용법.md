# Arca Studio

**미리보기에서 선택하고, 속성이나 코드를 고치면 함께 바뀌는 아카라이브 HTML 편집기입니다.**

## 열기

폴더 전체를 유지한 채 `index.html`을 브라우저에서 여세요. HTML·CSS·JS를 함께 사용하는 구조이며, 별도 패키지 설치나 빌드 과정은 없습니다.

## 처음 사용할 때

1. **HTML 불러오기**에서 기존 글의 HTML을 붙여넣습니다.
2. **미리보기에서 원하는 부분을 클릭**하면 트리·속성·해당 코드가 함께 선택됩니다.
3. 오른쪽에서 글자·색상·여백 등을 바꾸거나 아래 HTML을 직접 수정합니다.
4. **게시 예상 → 모바일**로 배치를 확인합니다.
5. **게시용 HTML 내보내기**에서 정리 결과를 보고 복사합니다.

화면 아래 코드 영역의 위쪽 경계선을 끌면 미리보기와 코드의 높이 비율을 바꿀 수 있습니다. PC·모바일은 **게시물 내용의 900px·360px 너비**를 뜻하며, ‘맞춤’ 배율로 화면 안에 축소해 보여줍니다.

상단 **‘편집기 · 다크 / 라이트’** 버튼으로 편집기 전체 테마를 바꿀 수 있습니다. 코드·구성 트리·속성·대화상자까지 함께 바뀌며 같은 브라우저에서 선택을 기억합니다. 중앙의 ‘☼ 라이트 / ☾ 다크’ 버튼은 **게시물 미리보기 배경**을 바꾸는 별도 설정입니다. 편집기 테마를 바꿔도 작성한 HTML과 내보내기 결과는 바뀌지 않습니다.

## 편집

- **블록 추가:** 대문·구역·접기·2열 카드·제목·본문·인용·목록·이미지·이미지 표·정보 표·링크·안내·구분선·코드 문장·정보 띠.
- **이동:** 트리 또는 미리보기에서 드래그합니다. 오른쪽 아래 ‘추가·이동 위치’에서 앞·뒤·안쪽을 고릅니다. 위·아래 버튼도 사용할 수 있습니다.
- **중첩 요소:** 트리에서 안쪽 요소를 고르거나 ‘상위 선택’으로 바깥 구역을 선택합니다.
- **본문:** 하위 태그가 없는 요소는 ‘내용’에서 바로 편집합니다. 하위 태그가 있는 요소 전체는 ‘내부 HTML 편집’에서 수정합니다.
- **코드:** 커서를 놓은 요소가 미리보기에서 표시됩니다. 코드는 원본 상태를 유지하며, 속성 편집은 선택한 요소의 시작 태그와 지정한 내용에만 적용됩니다.
- **접기:** 미리보기의 펼침 동작은 기본 상태를 저장하지 않습니다. ‘처음부터 펼쳐 놓기’ 속성으로 게시 시 기본 상태를 정합니다.
- **미디어:** 이미지 주소와 대체 텍스트를 편집할 수 있습니다. 동영상·iframe은 편집 중 실행하지 않고 위치 표시만 합니다.

## 이미지 여러 장

아카라이브 편집기에 이미지를 먼저 올리고, 이미지가 포함된 HTML을 가져오거나 이미지 주소를 한 줄씩 입력하세요. 1·2·3열 배치, 접기 없이 배치, 4장·8장씩 날짜별 접기가 가능합니다.

**블록 추가 → 여러 이미지 한 번에 넣기 → 붙여넣기 → 이미지 확인** 순서로 사용합니다. 각 이미지의 썸네일·실제 크기·로딩 성공/실패·주소 만료 시각을 확인하고, 필요한 이미지만 체크해 추가하세요. 썸네일을 누르면 확대해서 볼 수 있습니다. 문서에 넣은 뒤에는 트리에서 이미지를 선택하면 속성 패널에도 미리보기가 나타납니다.

`//ac.arca.live/…` 주소에는 `https:`를 붙여 읽고 내보냅니다. 이미지 추출 입력에서는 복사 과정의 `\<`, `\/`, `\_`를 정리하고, 맨 앞의 `<img`가 잘려 `src="…"`로 시작한 경우도 복구합니다. `key`·`expires`·주소 순서·중복 이미지는 임의로 지우지 않습니다. 일반 HTML 문서 불러오기는 원본을 보존하며, 이 복사 형식 복구는 ‘여러 이미지 넣기’에서 수행합니다.

주소에 적힌 만료 시각과 실제 이미지 로딩 결과는 별도로 보여줍니다. 로딩 실패만으로 만료·접근 제한·네트워크 문제 중 무엇인지 단정하지 않습니다. 주소를 새로 발급하거나 서명 값을 만들어내지는 않습니다. 실패한 이미지는 원본 글에서 현재 이미지 주소를 확인한 뒤 다시 넣어주세요.

이 편집기는 이미지 업로드 서버를 제공하지 않습니다. 임시 주소의 만료 여부는 게시 후 확인해야 합니다.

## 저장과 백업

- **저장 / Ctrl S:** 원본 HTML을 포함한 `.arca.json` 프로젝트 파일을 내려받습니다.
- **프로젝트 열기:** 내려받은 프로젝트로 계속 편집합니다.
- **원본 저장:** 편집 중인 원본 HTML을 내려받습니다.
- **자동 저장:** 같은 브라우저·주소의 저장 공간에 현재 작업을 보관합니다. 주소를 바꾸거나 브라우저 데이터를 지우면 이어지지 않을 수 있습니다.
- **백업:** 불러오기·새 문서·요소 삭제·내부 HTML 교체 전 원본을 최대 8개 보관합니다. 용량에 따라 개수는 줄어들 수 있습니다. 브라우저 저장 공간이 부족하면 파일 백업을 시도합니다.
- **Ctrl Z / Ctrl Shift Z:** 편집기 작업 되돌리기 / 다시 실행. 속성 입력칸에서는 브라우저의 텍스트 편집 단축키가 우선합니다.

중요한 문서는 프로젝트 파일로도 저장해 주세요. 일반 HTML은 8MB, 원본 이미지를 포함한 프로젝트는 150MB까지 열 수 있습니다.

## 게시용 HTML

제공된 가이드 v6.6을 기준으로 태그·인라인 CSS·주소·이벤트 속성을 검사합니다. 코드 예시에 쓰인 문자열은 실제 스타일과 구분합니다. 원본은 검사만으로 변경하지 않습니다.

게시용 내보내기는 차단 태그와 CSS를 제거하고, 필요한 태그를 정규화한 별도 결과입니다. 제거될 항목을 먼저 표시합니다. 제거가 많으면 배치가 달라질 수 있으므로 ‘게시 예상’을 확인하세요.

**실제 아카라이브 저장 결과를 복제한 것은 아닙니다.** 서버의 필터링, Froala 처리, 사이트 테마, 이미지 CDN 처리는 실제 게시 후 확인이 필요합니다. 미완성 태그나 잘못 중첩된 HTML은 브라우저가 보정하므로, 복잡한 원본은 복사본을 저장한 뒤 수정하세요.

## log_studio에 넣기

`arca-builder` 폴더 전체를 저장소 루트에 추가하고 기존 메뉴에 `./arca-builder/` 링크를 연결하면 됩니다. 현재 결과물은 로컬 파일이며 GitHub 저장소나 배포 설정은 수정하지 않았습니다.

## 파일 구성

- `index.html` — 화면 구성
- `style.css` — 편집기 디자인과 화면 크기 대응
- `core.js` — 원본 위치 매핑, 구조 이동, 가이드 검사와 게시용 출력
- `components.js` — 기본 문서, 16가지 블록과 색상
- `app.js` — 선택 연결, 편집, 파일 입출력, 저장과 백업

기본 색상은 `#8888CC`, `#DDAACC`, `#CCAA88`, `#BB6688`입니다. 외부 프레임워크·폰트 CDN·분석 스크립트 없이 실행됩니다. 사용자가 넣은 외부 이미지 주소는 미리보기 표시를 위해 해당 서버에서 불러옵니다.

## 원본 이미지로 편집하기 (v1.3)

1. **블록 추가 → 원본 이미지 · 주소 연결 → PC 원본 이미지 추가**를 누릅니다.
2. 썸네일과 **이미지 1, 2…**로 구분합니다. 긴 원래 파일명은 보조로 표시하며, 오른쪽 ‘이미지 설명’에서 이름을 바꿀 수 있습니다.
3. 문서 미리보기나 트리에서 이미지를 선택해 이동·크기 조절을 합니다. 인터넷 주소가 없어도 원본으로 표시합니다.
4. 같은 이미지를 아카라이브에 업로드한 뒤 HTML을 가져와 **원본 이미지 · 주소 연결** 창에 붙여넣습니다.
5. **주소 목록 읽기**를 누르고 각 원본에 연결할 주소를 고릅니다. 파일명으로 자동 대응하지 않습니다. 목록은 원본을 추가한 순서로 유지됩니다. 장수와 업로드 순서가 같을 때는 **같은 업로드 순서로 연결**을 쓸 수 있습니다. 확인 후 **주소 연결 적용**을 누릅니다.
6. **게시용 HTML 내보내기**를 사용합니다. 미연결·잘못된 주소가 있으면 먼저 연결하도록 안내합니다. 외부 URL의 실제 로딩이나 영구 유효성을 보장하는 검사는 아닙니다.

원본은 PNG·JPG·WebP·GIF·AVIF를 지원합니다. 한 장당 20MB, 현재 프로젝트의 원본 이미지 합계 100MB까지입니다. 원본은 브라우저 이미지 저장소에 보관하고 `.arca.json` 프로젝트 파일에도 포함합니다. 프로젝트는 150MB, 일반 HTML은 8MB까지 열 수 있습니다. 예전 v1 프로젝트도 열 수 있습니다. 중요한 작업은 **저장 / Ctrl S**로 프로젝트 파일을 보관하세요.

편집 코드의 `arca-local:…`는 원본 연결용 식별자입니다. `data-arca-publish`에 게시용 주소를 보관하고, 내보낼 때 일반 `src`로 바꿉니다. 원본 이미지 데이터·편집용 식별자는 게시용 HTML에 포함하지 않습니다. **원본 복사/원본 HTML 저장은 게시용이 아니며 이미지 파일도 포함하지 않습니다.** 원본 이미지를 함께 옮길 때는 프로젝트 저장을 사용하세요.

원본 이미지는 서버에 자동 업로드하지 않습니다. ‘게시 예상’도 배치 확인을 위해 원본을 표시하므로, 게시용 URL이 실제로 열리는지는 아카라이브에서 확인하세요. 서명된 주소의 key·expires를 지우거나 새로 발급하지 않습니다.

새 파일 `assets.js`는 원본 이미지 보관·프로젝트 입출력을 담당합니다. 이미지 주소 연결과 이동은 되돌리기 대상이며, 백업 복원에 필요한 원본은 브라우저 이미지 저장소에 남겨 둡니다.

## v1.4 원안 디자인 · 이미지 칸 드래그와 삭제

- 편집기 디자인은 제공된 **Arca Builder Design**의 차콜 배경, 노란 포인트, 왼쪽 트리·가운데 미리보기·오른쪽 속성, 하단 전체 너비 코드창을 기준으로 조정했습니다. 기존 라이트 테마와 편집 기능도 유지합니다.
- 원안의 IBM Plex Sans KR / JetBrains Mono 글꼴 파일과 SIL OFL 라이선스를 `fonts/`에 포함했습니다. 폰트 CDN 연결 없이 표시됩니다. 테마 변경은 게시물 HTML의 스타일을 바꾸지 않습니다.
- **파일 탐색기 → 미리보기의 이미지 칸**으로 파일 한 장을 끌어놓으면 해당 칸을 채웁니다. 기존 이미지 위에 놓으면 교체합니다. 여러 파일은 기존 ‘원본 이미지’ 창에서 추가하세요.
- **이미지 → 다른 이미지 칸**으로 끌면 이동합니다. 비어 있는 칸으로 옮기면 출발 칸이 비고, 이미 채워진 칸끼리는 이미지와 게시용 주소·설명이 서로 바뀝니다. 칸 자체의 크기·테두리는 유지합니다.
- **이미지 우클릭 → 이미지 삭제**는 칸을 유지하면서 이미지와 게시용 주소 연결을 제거합니다. **모바일은 이미지를 누른 다음 화면 아래 ‘이미지 삭제’**를 누릅니다.
- 이미지 넣기·교체·이동·삭제는 되돌리기 가능합니다. 삭제한 원본은 되돌리기/백업 복원을 위해 브라우저 이미지 저장소에 남습니다.

`reference-theme.css`가 원안에 맞춘 편집기 스타일을 담당합니다. `style.css`의 반응형/기능 스타일을 함께 사용하므로 둘 다 배포하세요. 원안의 정적인 화면과 완전히 같은 복제본은 아니며, 추가된 저장·이미지 연결·라이트 테마 기능을 함께 배치했습니다. 화면이 좁으면 상단 도구는 두 줄로 배치됩니다.

## v1.5 사용한 원본만 업로드 ZIP으로 저장

1. 이미지를 배치한 다음 **원본 이미지 · 주소 연결 → 사용한 원본 N장 ZIP 저장**을 누릅니다.
2. ZIP을 풀고 **images 폴더의 파일을 이름 오름차순(001, 002…)**으로 정렬합니다. 이 복사본들만 아카라이브에 번호순으로 업로드합니다.
3. 업로드된 이미지 HTML을 주소 연결 창에 붙여넣고 **ZIP의 images 폴더를 001부터 번호순으로 업로드했어요**를 체크합니다.
4. **주소 목록 읽기**를 누르면 해당 ZIP의 대응 순서로 연결안을 채웁니다. 확인 후 **주소 연결 적용 → 게시용 HTML 내보내기**를 누릅니다.

원본 폴더를 읽어 이름을 바꾸는 기능이 아닙니다. 사용자가 이미 STUDIO에 넣은 이미지 데이터에서 복사본을 만들며, **기존 파일을 수정·이동·삭제하지 않습니다.** 재인코딩하지 않으므로 내용과 화질은 원본과 같습니다. 파일 확장자는 저장된 이미지 형식에 따라 PNG/JPG/WebP/GIF/AVIF를 유지합니다. 같은 원본 ID가 여러 칸에서 쓰이면 ZIP에는 한 장만 넣고, 연결된 URL은 해당 칸들에 함께 적용합니다. 서로 별도로 넣은 파일은 ID가 다르므로 별도 이미지로 처리합니다. 웹 URL로만 넣은 이미지는 이 원본 ZIP에 포함하지 않습니다.

ZIP에는 images/001.png 같은 복사본, **이미지목록.html**(썸네일과 원래 파일명), 사용방법.txt, 연결정보.json을 넣습니다. 썸네일 목록은 ZIP을 푼 뒤 열어주세요. **프로젝트 저장(Ctrl S)**에는 원본 이미지와 ZIP 대응 정보를 함께 넣어 다음에도 이어서 연결할 수 있습니다. 연결정보.json 자체는 STUDIO 프로젝트 파일이 아닙니다.

자동 연결은 **ZIP 번호순과 아카라이브 HTML의 이미지 순서가 같다는 조건**으로 동작합니다. 아카라이브가 파일명을 해시로 바꾼 뒤에는 URL만으로 원본 내용까지 식별하지 못합니다. 업로드 중 순서가 달라졌으면 개별 주소 선택으로 고쳐주세요. 장수 불일치·지원하지 않는 주소·ZIP 저장 뒤 원본 추가/교체/삭제가 있으면 자동 연결하지 않습니다. 칸의 위치만 바꾼 경우에는 원본 ID로 대응하므로 유지됩니다. 다시 ZIP을 저장하면 가장 최근 묶음이 연결 기준이 됩니다.

새 파일 `upload.js`는 원본 복사본 ZIP 생성과 묶음 대응을 담당합니다.

## v1.6 이미지 편집 중 접기 유지

- 이미지 추가·이동·삭제·되돌리기 후에도 미리보기에서 열고 닫은 접기 상태를 유지합니다. 이 상태는 게시용 HTML의 `open` 속성을 바꾸지 않습니다.
- 이미지를 삭제한 자리는 깨진 아이콘 대신 **이미지를 여기에 놓으세요** 안내로 표시됩니다. 같은 칸에 다시 파일을 끌어놓으면 됩니다.
- 안내 이미지는 미리보기에서만 표시하며 게시용 HTML에 포함하지 않습니다. 새 문서를 불러오면 해당 문서의 초기 접기 상태로 시작합니다.
